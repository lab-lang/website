This page is for building and running the compiler itself: useful if you're
contributing to the toolchain, writing a new backend, or want to inspect
compiler internals directly. If you want to write Lab programs, the
[playground](/playground) runs the compiler in your browser with nothing to
install, and [Your first program](/docs/guide/first-program) is where the
docs pick up from there.

The toolchain is a Rust workspace. There is no published release yet, so
build it from source, from the sibling `lab` repository.

```shell
cargo build --workspace
```

`cargo build` produces two binaries you'll use directly: `lab`, the
package-aware CLI, and `labc`, the single-file developer compiler used
throughout this documentation for `--emit` inspection. A third, `lab-opt`,
operates on textual LAIR rather than source and is covered in
[CLI reference](/docs/compiler/cli-reference). They land in
`target/debug/`, so put that on your `PATH` to run them by name below.

## Scaffold a project

```shell
lab new my-plasmid
```

`lab new` writes a minimal package:

```text
my-plasmid/
  lab.toml
  .gitignore
  src/
    programs/
      main.lab
```

`lab.toml` declares the package name, version, edition, and build entry
point. Source lives under `src/`, conventionally split into `designs/`,
`workflows/`, and `programs/`, and a bench to compile for lives under
`targets/`. `lab new` only scaffolds `src/programs/main.lab` to start.
[Modules and packages](/docs/guide/modules-and-packages) covers the full
manifest shape and module naming convention.

## Check, build, and inspect

```shell
lab check my-plasmid
lab build my-plasmid
lab metadata my-plasmid
```

`lab check` resolves imports, type-checks, and verifies material flow for a
single `.lab` file or a whole project. `lab build` does the same and then
writes one `*.module.json` artifact per module plus a package index and a
`lab.lock` file under `.lab/build/`, and compiles for the target the manifest
names; pass `--no-target` to stop at portable module IR. `lab metadata`
prints the resolved manifest and module list without compiling anything,
useful for confirming `lab.toml` resolved the way you expect before a build.

Every `lab` subcommand accepts a global `--json` flag for machine-readable
output, which is what the language server and other tooling consume instead
of parsing human-readable text.

## Inspecting a single file

For working on the language itself, or on a single design outside a package,
`labc` is faster to iterate with: it takes one `.lab` file and an `--emit`
target directly, without a `lab.toml`.

```shell
labc reporter.lab --emit module-ir
```

See [CLI reference](/docs/compiler/cli-reference) for the full table of
`--emit` targets, from a human-readable summary through to a generated
Opentrons automation bundle.
