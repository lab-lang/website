## Layout

Lab is indentation-sensitive, like Python. Tabs are rejected. Braces
construct or destructure typed data, parentheses call or group, brackets
build collections, and angle brackets carry type arguments, covered in
[The two arrows](/docs/guide/the-two-arrows).

## Comments and documentation

`//` starts a line comment and runs to the end of the line. It is the only
comment form: `#` is not a comment character, and `/*` opens documentation
rather than a block comment.

Documentation is a `/** … */` block standing immediately above the
declaration it describes. Unlike a comment it is part of the declaration:
the parser attaches it to the syntax tree, it travels in the module's
checked interface, and editors show it on hover and in completions. A module
documents itself with `/*! … */` at the top of its file, above the imports.

```lab
/*! Two composite transcription units, each a promoter driving a reporter. */

use std.bio.designs

/**
 * Assemble the GFP reporter plasmid.
 *
 * Takes no material input, so the compiler places this build ahead of
 * everything that consumes the plasmid.
 */
workflow assemble_composite_plasmid_1() -> Material<Plasmid>:
  product <- realize composite_plasmid_1
  return product
```

Following [PEP 257](https://peps.python.org/pep-0257/), a docstring opens
with a one-line summary that stands on its own; anything further follows a
blank line. Documentation always has a subject, so a `/** */` that precedes
an import or precedes nothing is an error rather than a comment that
silently goes nowhere. An aside inside a workflow body is a `//` comment.

## The whole vocabulary

The keywords are orchestration mechanics only. The _vocabulary_, meaning
`plasmid`, `strain`, and any word a package declares with `artifact`, is not
in this table and is not in the parser. Laboratory verbs such as `realize`,
`transform`, and `dispose` are library operations, not keywords; see
[Action contracts](/docs/guide/action-contracts) for the full list.

| Group                 | Keywords                                             |
| --------------------- | ---------------------------------------------------- |
| Modules               | `use`                                                |
| Declaration shapes    | `record`, `circuit`, `artifact`, `workflow`, `state` |
| Classification        | `role`, `is`, `any`                                  |
| Provenance            | `build`, `buy`                                       |
| Schemas and contracts | `declares`, `require`, `accept`, `across`            |
| Control flow          | `if`, `else`, `for`, `in`, `match`, `case`, `return` |
| Reactive control      | `when`, `every`, `after`, `emit`                     |
| Boolean operators     | `and`, `or`, `not`                                   |

## Callable signatures

Circuits and workflows are both called, so both declare a callable signature
in their header rather than inside their block. Parentheses are required
even with zero parameters, and a result declaration after `->` is mandatory;
there is no implicit return type.

```lab
workflow preserve_sample(source: Material<Plasmid>) -> Material<Plasmid>:
  return source
```

Only a workflow may name its results, using a parenthesized typed field
list, which lets it return several values together:

```lab
workflow build_reporter() -> (
  strain: Material<Strain>,
  plate: Material<Plate>,
):
  product <- realize reporter
  dependencies = [product]
  cells <- provision DH5alpha
  strain, culture <- transform reporter_host from dependencies into cells
  culture <- recover culture for 1 h
  plate <- plate culture on chloramphenicol
  return strain, plate
```

A circuit produces one value, and its block holds only what it is built
from:

```lab
circuit regulated_expression(
  promoter: Promoter<Trigger: Signal>,
  coding: CDS<Product: Protein>,
) -> Circuit<Trigger, Product>:
  layout:
    promoter
    coding
```

`-> None` and `return None` are valid for a workflow with no meaningful
result. `-> ()` is not: an explicitly empty tuple type is rejected rather
than treated as a synonym for `None`.

## Typed external identities

An item a supplier lists enters through a `buy` declaration against an
imported kind. There are no string identifiers scattered through a design:

```lab
use std.bio.designs

buy part J23101
buy backbone pSB1C3
buy chassis DH5alpha
buy antibiotic chloramphenicol

buy restriction_enzyme BsaI:
  digest_temperature = 37 C
```

A bought item's external identity, meaning what a supplier's order names,
defaults to the declared name. It is written as an `identity` property only
where the two differ, so renaming a source symbol and changing an external
identifier stay distinct operations:

```lab
buy plasmid reference_gfp:
  identity = "Addgene-#134516"
  sequence = dna("GCTAGCGGATCCATGACCATGATTACGCCAAGCTTGAATTC")
```

A `buy` declaration creates a typed _name_; it does not resolve
availability, lot, or provenance. A design references these names in its
properties (`backbone = pSB1C3`, `restriction_enzyme = BsaI`), and a
workflow references them in action phrases (`provision DH5alpha`, `plate
culture on chloramphenicol`). Source symbols are values regardless of
capitalization: `J23101`, `BsaI`, and `DH5alpha` do not become types because
their names begin with capitals.
