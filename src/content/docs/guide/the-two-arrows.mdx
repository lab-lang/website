Lab's punctuation is small and each symbol does exactly one thing:

| Form              | Meaning                                         |
| ----------------- | ----------------------------------------------- |
| `:`               | Opens a declaration or control block            |
| `name = value`    | Declares a property on a biological declaration |
| `name: Type`      | A field, parameter, or annotation               |
| `{ name: value }` | Constructs or destructures typed data           |
| `[ … ]`           | Collection literal                              |
| `< … >`           | Type arguments                                  |
| `=`               | Deterministic evaluation or state transition    |
| `<-`              | Durable physical or external effect             |
| `->`              | Declares a circuit or workflow result           |
| `//`              | Line comment                                    |
| `/** … */`        | Documentation for the declaration below it      |
| `/*! … */`        | Documentation for the module the file opens     |

## `=` may be replayed. `<-` may not.

The distinction that matters most is between `=`, which replay may
re-evaluate, and `<-`, which it must never repeat. `culture = culture + 1`
is pure computation, safe to re-run from a checkpoint. `culture <- transform
construct into cells` is a chemical transformation performed on a real
sample; running it twice would produce a different physical world, not the
same answer computed again. The durable runtime that enforces this at
execution time doesn't exist yet, but the checker already distinguishes the
two everywhere a workflow is written.

```lab
workflow build_reporter() -> (
  strain: Material<Strain>,
  plate: Material<Plate>,
):
  product <- realize reporter
  dependencies = [product]
  cells <- provision DH5alpha
  strain, culture <- transform reporter_host from dependencies into cells
  culture <- recover culture for 1 h
  culture <- dilute culture
  plate <- plate culture on chloramphenicol
  return strain, plate
```

Every `<-` line here is a durable command: a physical action bound to a
recorded completion event. None of it may be silently re-run. `dependencies
= [product]` is the one line replay is free to re-evaluate, because building
a list is arithmetic rather than an event.

## Inside a declaration body, `=` and `:` divide cleanly

The same two marks separate a declaration's values from its types. `=`
associates a name with a value, and `:` gives a name a type, which is why an
artifact's schema is written with colons and an instance of it with equals:

```lab
artifact Plasmid:
  sequence?: DNA
  backbone?: Backbone

plasmid reporter:
  sequence = dna("ACGTACGT")
  backbone = pSB1C3
```

A property's value is a deterministic expression, evaluated once and never
repeated: it is definitively not an effect, which is what `=` says and `<-`
would deny.

## Operand modes: what an action does with what you hand it

Every durable action's contract states how it treats each operand it
receives:

| Mode     | Meaning                                                                   |
| -------- | ------------------------------------------------------------------------- |
| `copy`   | Freely reusable information; the action reads it, ownership is unaffected |
| `borrow` | Observes a material without consuming it; ownership does not change       |
| `take`   | Transfers ownership of a material into the action                         |

`provision DH5alpha` takes a `copy` operand: `DH5alpha` is a typed external
identity declared with `buy`, not physical material, so there's nothing to
give up. `transform reporter_host from dependencies into cells` takes `take`
operands: both the dependency material and `cells` are consumed, and the
workflow can no longer use either afterward; only the newly returned
`strain` and `culture` are live. `capture image of plate` takes
`plate` with `borrow`; the plate is observed, not consumed, and remains
available to `plate` for the next reading. This is exactly the information
[material flow](/docs/guide/material-flow-and-acceptance) verifies against
every use in a workflow body.
