`lab` is the package and facility CLI. `labc` inspects one source file. `lab-opt` parses and transforms textual LAIR. All `lab` commands accept the global `--json` flag, including after the subcommand.

## `lab`

| Command                                               | Does                                                                                                                                                             |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lab new <path> [--name <name>]`                      | Creates a package with `lab.toml` and `src/programs/main.lab`.                                                                                                   |
| `lab check [<path>]`                                  | Checks a source file or package and validates configured inventory and adapter bindings.                                                                         |
| `lab build [<path>] [--out-dir <dir>]`                | Writes portable compiler artifacts and, when configured, the facility solution, Allocated Procedure LAIR, adapter invocations, reviewed plan, and Asset bundles. |
| `lab plan [<path>] [--out-dir <dir>]`                 | Writes only the complete facility-planning and adapter-lowering bundle.                                                                                          |
| `lab adapters describe [--driver <id>]`               | Prints `lab.adapter-catalog.v3` or one descriptor, including capabilities, control modes, formats, services, and profile schema.                                 |
| `lab adapters default <driver> [--name <name>]`       | Prints one adapter's complete canonical reference profile.                                                                                                       |
| `lab adapters validate <driver> <profile>`            | Parses and semantically validates a profile through the explicit driver.                                                                                         |
| `lab adapters render <driver> <profile>`              | Prints the canonical validated profile.                                                                                                                          |
| `lab run <plan-dir> --dry-run`                        | Validates the reviewed plan and narrates the complete execution without touching hardware.                                                                       |
| `lab run <plan-dir> --simulate`                       | Executes through configured simulation adapters.                                                                                                                 |
| `lab run <plan-dir> [--asset-endpoint <IRI=address>]` | Executes supported live adapters after full preflight and confirmation.                                                                                          |
| `lab metadata [<path>]`                               | Prints the resolved manifest and module list.                                                                                                                    |
| `lab update [--check]`                                | Checks for or installs a newer `lab`, `labc`, and `lab-opt` release.                                                                                             |

`lab build` defaults to `.lab/build`; `lab plan` defaults to `.lab/plan`. Relative `--out-dir` values are resolved from the project root. There is no `--target`, `--no-target`, or `[target]` table: the selected SBOLInventory Facility and its explicitly bound Assets determine eligible adapter invocations.

The runtime options are:

- `--dry-run` validates and narrates without executing.
- `--simulate` selects simulation execution and conflicts with `--dry-run`.
- `--yes` skips only the initial confirmation; manual steps and physical handoffs still require the operator.
- `--resume` continues the exact reviewed plan from its durable ledger and rejects digest changes.
- `--asset-endpoint <ASSET_IRI=ADDRESS>` supplies a repeatable non-portable endpoint for a networked Asset.

## Typical facility workflow

```shell
lab check examples/golden-gate
lab adapters describe --driver opentrons.ot2
lab build examples/golden-gate
lab run examples/golden-gate/.lab/build --dry-run
```

`lab build` reports every biological product and every compiler, facility, Asset, protocol, document, and reviewed-plan output path. Use `lab plan` when only the reviewed facility bundle is needed:

```shell
lab plan examples/ebef/acceptance
lab run examples/ebef/acceptance/.lab/plan --simulate
```

## `labc`

```shell
labc <source.lab> --emit <representation>
```

`labc` is a single-file compiler-inspection tool. It has no inventory, target, adapter, device, or filesystem bundle mode. Multi-module compilation, SBOLInventory ingestion, global allocation, adapter lowering, and reviewed-plan construction belong to `lab` through the shared project service.

| `--emit` value       | Produces                                                                 |
| -------------------- | ------------------------------------------------------------------------ |
| `human`              | A readable summary of the checked module.                                |
| `source-ast`         | The spanned source AST as JSON.                                          |
| `module-ir`          | The checked portable module as JSON.                                     |
| `design-intent-lair` | Verifier-valid facility-independent Design and Intent LAIR.              |
| `refined-lair`       | Verifier-valid Method alternatives with Procedure and Capability graphs. |
| `planning-problem`   | The facility-independent `lab.planning-problem.v4` projection.           |

## `lab-opt`

```shell
lab-opt [<input>] --pass-pipeline "builtin.module(check-material-linearity)"
```

`lab-opt` reads textual Pliron IR from a file or standard input and runs a module-anchored pass pipeline. `--input-stage` requires the input to satisfy a named `IrStage`; `--verify-each` verifies before and after every pass; `--print-before-all` and `--print-after-all` write snapshots to `--ir-printing-dir`; and `--list-passes` prints the registered passes.

The textual tool exposes Design, Workflow, Method, Procedure, Capability, and Allocation operations and verifies `design-intent`, `refined-alternatives`, and `allocated-procedure`. Source-to-Method refinement, problem extraction, solving, and solution application are compiler APIs rather than dynamic `lab-opt` passes. The `check-material-linearity` pass validates affine material use in an Allocated Procedure module.
