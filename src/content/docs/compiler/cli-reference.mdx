Three binaries, three different jobs. `lab` is the package-aware CLI a
project actually uses; `labc` compiles one source file and can `--emit` any
pipeline stage; `lab-opt` never touches source at all: it parses, verifies,
and transforms textual LAIR directly.

## `lab`

| Command | Does |
| --- | --- |
| `lab new <path>` | Scaffolds a package: `lab.toml` plus `src/programs/main.lab`. |
| `lab check <path>` | Resolves, type-checks, and verifies material flow for one file or a whole package. |
| `lab build <path> [--out-dir <dir>]` | Checks, then writes one `*.module.json` per module, a package index, and a `lab.lock`. |
| `lab metadata <path>` | Prints the resolved manifest and module list without compiling. |

Every subcommand accepts a global `--json` flag for machine-readable output.

## `labc`

```shell
labc <source.lab> --emit <target> [--output-dir <dir>] [--inventory <file.json>]
```

| `--emit` value | Produces |
| --- | --- |
| `human` (default) | A readable summary of the checked module. |
| `source-ast` | The spanned source AST, as JSON. |
| `module-ir` | The checked module, as JSON: the portable frontend boundary. |
| `automation-json` | The OT-2 execution plan, as JSON. |
| `manual-protocol` | A Markdown protocol for a person to follow by hand. |
| `opentrons-assembly` | The generated Python assembly script. |
| `opentrons-transformation` | The generated Python transformation script. |
| `opentrons-plating` | The generated Python plating script. |
| `automation-bundle` | Every OT-2 artifact together, written to `--output-dir`. |
| `dependency-plan` | The resolved build-dependency graph, given `--inventory`. |
| `full-build-bundle` | Dependency planning plus an OT-2 bundle per artifact, given `--inventory` and `--output-dir`. |

## `lab-opt`

```shell
lab-opt [<input>] --pass-pipeline "builtin.module(protocol-check-material-linearity)"
```

`lab-opt` reads textual Pliron IR (a file path, or `-` for standard input,
the default) and runs a module-anchored pass pipeline against it, such as
`builtin.module(protocol-check-material-linearity)`, the one pass registered
today (see [LAIR dialects](/docs/compiler/lair-dialects)). `--input-stage`
requires the input to already satisfy a given `IrStage` contract before
running anything. `--verify-each` (on by default) re-verifies the complete
IR before and after every pass; `--print-before-all` and `--print-after-all`
capture snapshots to `--ir-printing-dir` for inspecting exactly what a pass
changed. `--list-passes` prints the registered target-independent passes and
exits.
