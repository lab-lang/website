The Inheco ODTC is an independent SBOLInventory Asset exposing a `ThermalCycling` capability offering. It is not a station inside a workcell and not a compiler target. A facility-wide plan may allocate a thermal Procedure task to it and insert explicit movement between the ODTC and whichever Asset handles the plate before or after cycling.

## Bind the Asset

```toml
[[execution.adapters]]
asset = "https://example.org/my-lab/inheco_odtc"
driver = "inheco.odtc"
profile = "adapters/inheco-odtc.toml"
```

The adapter supports the exact `ThermalCycling` capability under the SBOLInventory `Sila2` control mode. It provides planning compatibility, simulation, and runtime execution. It does not provide a whole-program lowerer today; it consumes device-neutral `lab.thermocycle-run.v0` child documents produced by facility coordination.

Network addresses and credentials do not belong in the portable manifest or inventory graph. Runtime receives the exact Asset endpoint explicitly:

```shell
lab run .lab/plan --asset-endpoint https://example.org/my-lab/inheco_odtc=169.254.10.40:8080
```

## Device-neutral reviewed document

`lab.thermocycle-run.v0` names the plate, repeated temperature steps, optional ramp and lid settings, final hold, and fill volume. The document does not name Inheco; the reviewed plan's exact Asset and adapter binding chooses the executor.

```json
{
  "format": "lab.thermocycle-run.v0",
  "id": "transformation_heat_shock",
  "title": "Cold hold and heat shock",
  "plate": "reaction_plate",
  "profile": {
    "stages": [
      {
        "steps": [
          { "celsius": 4.0, "hold_seconds": 1800.0 },
          { "celsius": 42.0, "hold_seconds": 60.0 },
          { "celsius": 4.0, "hold_seconds": 120.0 }
        ],
        "repeats": 1
      }
    ]
  },
  "final_hold_celsius": 4.0,
  "fill_volume_ul": 22.0
}
```

The runtime validates the complete profile against the device envelope before any motion, controls the ODTC over its SiLA HTTP/XML protocol, and represents plate loading and unloading as explicit human handoffs. Simulation computes durations from ramps and holds.

## Current boundary

The adapter is experimental. The device reports completion but not continuous run progress. Some schema fields are not yet emitted by the current compiler path, and fill-volume handling still needs a complete end-to-end audit. Physical use requires local qualification. The Method/Procedure/Capability architecture will make thermal tasks and their material ports first-class rather than recovering them from one plasmid-build plan.
