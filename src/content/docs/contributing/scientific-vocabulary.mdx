Use this path when Lab needs a new scientific term, material state, action, or reusable workflow. You will edit a Lab package and consume it from Python. Rust is not required. The result is a checked interface that other packages and Python authors can import.

## Start from the scientific package

The [scientific-package example](https://github.com/lab-lang/lab/tree/master/examples/contributing/scientific-package) provides a complete starting point. Work in a copy when creating your own package; the commands here verify the checked-in example from the repository root.

| File               | Your contribution                                           |
| ------------------ | ----------------------------------------------------------- |
| `lab.toml`         | Package identity, dependencies, and Method catalog paths    |
| `src/science.lab`  | Public scientific declarations and their documentation      |
| `src/main.lab`     | A small workflow exercising the declarations                |
| `protocol.py`      | The same action used through its generated Python interface |
| `bindings/python/` | Generated `.py` modules and `.pyi` typing stubs             |

Install the [development SDK and CLI](/docs/development-setup#choose-your-development-setup) before running the example.

## Declare the action

This is the example's action declaration:

```lab
use std.bio.designs
use std.lab.plasmid

action homogenize <sample> -> prepared:
  sample: take Material<Medium>
  prepared: Material<Medium> continues from sample
```

`take` transfers ownership of the sample to the action. `continues from sample` makes the result part of that same physical lineage. The declaration says what the operation means and what a caller receives. Its Method supplies the preparation steps.

Add related kinds, facets, and actions in the package as needed. See [Action contracts](/docs/language/action-contracts) for ownership and results, and [Values, roles, and kinds](/docs/language/values-roles-and-kinds) for the vocabulary those contracts use.

## Generate and consume the Python interface

```shell
cargo run --locked -p lab-cli -- check examples/contributing/scientific-package
cargo run --locked -p lab-cli -- bindings python examples/contributing/scientific-package
```

The compiler writes `bindings/python` inside the package. The action retains its exact Lab definition identity; Python authors import the generated callable:

```python
from contribution_example.science import homogenize
```

The [complete consumer](https://github.com/lab-lang/lab/blob/master/examples/contributing/scientific-package/protocol.py) performs that action inside a Python workflow and calls `lab.check(..., project=project)` followed by `lab.refine(..., project=project)`. The package context supplies the checked declarations and Method catalog.

```shell
PYTHONPATH=examples/contributing/scientific-package/bindings/python \
  crates/lab-python/.venv/bin/python examples/contributing/scientific-package/protocol.py
```

The expected result is `Package action compiled and refined through its pipetting Method.` This example ends at refinement because it has no facility inventory or instrument binding.

## Finish the contribution

Include a small valid consumer and an example the checker must reject, such as an incompatible material type. Regenerate bindings after changing the public declaration; the generated signatures should agree with the Lab types. The repository checks this boundary with:

```shell
crates/lab-python/.venv/bin/pytest crates/lab-python/tests/test_contributing.py
```

For a vocabulary-only contribution, a checked interface and consumer establish the result. For an action you want to compile into work, continue to [Write a pipetting method](/docs/contributing/pipetting-methods). A new action name alone does not supply its Procedure implementation.
