Editor support is built as one analysis core with two thin adapters on top,
rather than as logic duplicated per host.

## `lab-ide`: the analysis core

`lab-ide` is platform-neutral: it depends on `lab-language` alone, nothing
about LSP or the browser. Its central type, `Workspace`, holds a set of open
documents and provides:

- Diagnostics, with secondary spans and a `help` line where one applies
- Document symbols
- Completions: keywords, plus top-level declarations from open documents,
  each carrying the documentation its declaration was written with
- Hover, including on a `use` path, which hovers the module it imports
- Definition and references
- Rename: name-based, works across documents, and is aware of comments and
  strings so it doesn't rename inside them
- Semantic tokens
- Formatting, currently whitespace-only: trailing whitespace trimmed, a
  final newline ensured. No syntax-aware reformatting yet.

`Workspace` itself is I/O-free, so it cannot read a manifest. A host that can
supplies each document's module name, and `lab-language-server` does: on open,
it discovers the package holding the file and loads every source module in it.
A `use` of a package sibling therefore resolves whether or not that sibling is
open, and modules carry the name their manifest gives them rather than one
guessed from a path. A file outside any package keeps the path-derived name,
which is what the browser playground relies on.

Definition, references, and rename still only see loaded documents: there's
no persistent, project-wide symbol index yet, so a file outside the open
package drops out of those queries.

## Two adapters, one core

`lab-language-server` wraps `Workspace` with `lsp-server`/`lsp-types` over
stdio, handling `didOpen`/`didChange`/`didClose` plus requests for
completion, hover, definition, references, rename, document symbols,
semantic tokens, and formatting. It's the server any LSP-compatible editor
talks to. `lab-ide-wasm` re-exposes the same `Workspace` through
`wasm-bindgen` instead, for embedding directly in a browser or another
non-LSP host: it's what the [playground](/playground) on this site runs
on.

Because both adapters call into the same `lab-ide` core, editor behavior
can't drift between the LSP server and an embedded browser integration: a
completion or diagnostic means the same thing either way.

## VS Code extension

An editor extension for VS Code and Cursor lives under `editors/vscode/`,
including TextMate syntax highlighting, snippets, and the client wiring to
launch `lab-language-server` over stdio.
