Editor integrations use the same language model as compilation. `lab-ide` turns source analysis into diagnostics and editing operations. The language server and browser bridge expose those operations to their hosts.

This boundary is useful when adding a new editor or an authoring feature. It provides source understanding; facility planning and device generation belong to the separate [project application service](/docs/compiler/pipeline#where-the-code-lives).

## Choose the code boundary

| Contribution                                          | Where it belongs                                                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Improve diagnostics, hover, completion, or navigation | [`lab-ide`](https://github.com/lab-lang/lab/tree/master/crates/lab-ide/src), using the shared checker in `lab-language`         |
| Connect an LSP-compatible editor                      | [`lab-language-server`](https://github.com/lab-lang/lab/tree/master/crates/lab-language-server/src) and the editor's LSP client |
| Embed source analysis in a browser                    | [`lab-ide-wasm`](https://github.com/lab-lang/lab/tree/master/crates/lab-ide-wasm/src)                                           |
| Add VS Code or Cursor client behavior                 | [`editors/vscode`](https://github.com/lab-lang/lab/tree/master/editors/vscode)                                                  |

Put language-analysis behavior in the core so both hosts can use it. Keep protocol translation, document loading, and client presentation in the relevant integration.

## The shared analysis core

`lab-ide::Workspace` holds loaded documents and answers queries about them. Its language dependency is `lab-language`; the analysis core does not depend on LSP or browser APIs.

It currently provides:

- Diagnostics, including secondary source spans and contextual help.
- Document symbols, keyword and declaration completion, and hover documentation.
- Definition, references, and name-based rename across loaded documents. Rename avoids comments and strings.
- Semantic tokens for highlighting.
- Basic formatting: trimming trailing whitespace and ensuring a final newline.

Formatting is not yet syntax-aware. Definition, references, and rename use identifier names across loaded documents, without a persistent project-wide symbol index. They do not yet distinguish every same-named symbol by resolved declaration identity, so a rename is not a scope-aware refactoring.

## Who loads the project

`Workspace` performs no file I/O. A host supplies source text and, when available, the module name determined by the package manifest.

The language server discovers the package containing an opened file and loads its source modules. Imports of package siblings can therefore resolve even when those files are not open in the editor. Files outside a discovered package use path-derived names.

The browser playground supplies its own documents. It does not acquire the desktop language server's filesystem or package-loading behavior merely by using the same analysis core. A feature that needs more documents must define how its host obtains and supplies them.

## Language server and browser bridge

`lab-language-server` exposes `Workspace` through the Language Server Protocol over standard input and output. It handles document lifecycle notifications and requests for completion, hover, definition, references, rename, symbols, semantic tokens, and formatting.

`lab-ide-wasm` exposes the same analysis through `wasm-bindgen`. The website's [playground](/playground) uses this WebAssembly bridge. For a given core revision and document set, both hosts call the same language-analysis implementation.

The website commits a generated compiler bundle. It can lag behind the native checkout until rebuilt, so matching architecture does not imply matching installed revisions. Changes to the analysis core need the relevant native and browser consumers rebuilt before both expose the new behavior.

<span id="vs-code-extension" />

## VS Code and Cursor

The extension under `editors/vscode/` provides TextMate highlighting, snippets, and the client that launches `lab-language-server` over standard input and output. New protocol-independent analysis belongs in `lab-ide`; editor-specific commands and presentation belong in this client.

A contribution should include the source example that demonstrates the behavior and a check at the boundary it changes. A core analysis change should be exercised with the relevant loaded document set; a host integration should also demonstrate its document loading and protocol translation.
